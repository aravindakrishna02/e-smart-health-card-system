# Contributing

Thanks for contributing to the E-Smart Health Card prototype.

## Guidelines
- Keep demo data fictional.
- Explain new features and known limitations in the README.
- Never commit passwords, API keys, cloud credentials, patient records, or other private data.
- For backend work, add tests for authentication, authorization, validation, and audit logging.
- Do not describe a security feature as implemented until it is enforced and tested server-side.

## Proposed workflow
1. Create a feature branch.
2. Make a focused change.
3. Test the relevant flow in a current browser.
4. Update documentation.
5. Open a pull request describing the change and test results.
